# Порция

Проект ВКР по теме «Разработка приложения рекомендательной системы для планирования рациона питания с применением искусственного интеллекта».

Приложение помогает составить меню на день или неделю, рассчитать порции и подготовить список продуктов для покупки. Клиент написан на Kotlin, сервер — на Python с FastAPI. Для работы с ИИ используется Ollama.

## Что реализовано
- Профиль пользователя, пищевые ограничения и предпочтения.
- Меню на 1 или 7 дней, замена блюд и готовка с запасом.
- Каталог из 79 блюд с составом и инструкциями.
- Учёт продуктов дома и список покупок с отметками.
- Разбор пожеланий к меню через ИИ.
- Поиск предложений магазинов и карта с пешими маршрутами.

ИИ выбирает блюда из каталога. Калорийность, количество продуктов и ограничения проверяются на сервере. Цены блюд в меню являются плановой оценкой; поиск предложений магазинов не подтверждает полную стоимость корзины или наличие товара.

## Структура
`Android/` — проект Android Studio, интерфейс и тесты клиента.

`Server/` — API, база данных, каталог, расчёты, интеграции и тесты сервера.

## Запуск
1. В `Server/` создать `.env` по примеру `.env.example`, указать собственные пароли базы и JWT, адрес Ollama и имя установленной модели.
2. Из `Server/` выполнить `docker compose up -d --build`. Модель Ollama нужно запустить отдельно; её адрес должен быть доступен из контейнера API.
3. Открыть `Android/` в Android Studio. Адрес своего API задать через переменную окружения `PORCIA_API_BASE_URL` или свойство `porciaApiBaseUrl` в пользовательском `~/.gradle/gradle.properties` за пределами проекта. URL должен оканчиваться `/`.
4. Собрать и запустить приложение. Без настройки адреса используется неработающий пример `https://api.example.invalid/`.

Подробности запуска и проверок находятся в README каждой части. Личные адреса сервера, действующие ключи, базы пользователей и APK в репозиторий не включены. Внешние адреса магазинов и карт относятся к публичным источникам данных.

## Проверка
Сервер: `python -m pytest -q` из `Server/` после установки зависимостей и pytest, с отдельными тестовыми `DATABASE_URL` и `JWT_SECRET`.

Android: `gradlew.bat :app:assembleDebug` и `gradlew.bat :app:testDebugUnitTest` из `Android/`. Для Linux/macOS используется `./gradlew`. Особенности запуска тестов из кириллического пути Windows описаны в `Android/README.md`.

Адрес, заданный при сборке, попадает в APK. Сборку с личным адресом сервера не следует публиковать вместе с исходниками.
